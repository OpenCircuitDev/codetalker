# Daily Upstream Check — Routine Spec

**Schedule:** Daily at 09:00 UTC.
**Fires from:** Anthropic cloud (remote agent) — full repo checkout, no local-machine access.
**Purpose:** Detect upstream changes to the AI-coding platforms codetalker integrates with, and open PRs for any adapter updates needed.

---

## Mission

You are running unattended in a fresh remote Claude Code session. The repo `OpenCircuitDev/codetalker` is already checked out. Your job: check each upstream source listed below for new releases or breaking changes since the **last** run, then either (a) open a PR proposing the adapter update or (b) append a "no change" line to today's daily log.

You are NOT running interactively. There is no user to ask. Make reasonable judgment calls and document them.

## Decision logic per source

For each source, compare the freshly-fetched version against `state.json`:

1. **No change** — same version as last run. Continue.
2. **Patch bump** (e.g., 1.2.3 → 1.2.4) — fetch release notes if available; note in today's daily log; do NOT open a PR unless release notes mention "breaking" or "deprecat" keywords.
3. **Minor bump** (e.g., 1.2.x → 1.3.0) — fetch release notes; review for changes that affect codetalker's adapter for this platform. If any: open a PR (see PR template below). If none: note in daily log.
4. **Major bump** (e.g., 1.x → 2.0) — always open a PR titled `chore: investigate <source> v<X> impact on codetalker adapter`. Even if no immediate breaking change, major bumps warrant human review.

Skip sources where the fetch fails (network, 404, parse error). Log the failure in the daily log under a "Fetch failures" section, do not error out the whole routine.

## PR template (when opening a PR)

Branch name: `chore/upstream-<source-key>-v<new-version>`
Title: `chore: update <source-name> adapter for v<new-version>`
Body:

```markdown
**Upstream change detected:** <source-name> v<old> → v<new> (<bump-type>)

**Release notes / changelog excerpts (relevant lines):**
> <quoted snippets>

**Impact on codetalker:**
- <bullet on which adapter file(s) might need changes>
- <bullet on any new APIs to leverage>
- <bullet on any deprecations to handle>

**Suggested action:**
- [ ] Verify adapter compatibility with `<source-name>` v<new>
- [ ] Update integration tests if the new version is reachable in CI
- [ ] Document any new features users can take advantage of

**Auto-generated by daily-upstream-check routine.**
```

For PR creation: use `gh pr create` after committing the daily log change on a branch. Push branch then create the PR against `main`.

## Daily log file

Append one line per source to `docs/upstream-log/YYYY-MM.md` (current month). Create the file with a header if it doesn't exist. Format:

## After all sources processed

1. Save the updated `state.json`.
2. Commit the state.json + daily log changes to `main` directly (these are routine bookkeeping, not code changes).
   - Commit message: `chore(routines): daily upstream check 2026-05-10`
   - The state file commits are non-controversial — no PR needed for them.
3. PRs for adapter updates remain open for human review (you opened them earlier in this run).
4. Push to `origin main`.

## Hard rules

- **Do NOT modify** any code outside `docs/upstream-log/`, `.claude/routines/`, or branches you create explicitly for adapter PRs. Especially: do NOT touch `core/`, `companion-android/`, `webui/`, existing specs, or uncommitted work.
- **Do NOT skip hooks** (no `--no-verify`).
- **Do NOT force push** to main.
- **Do NOT delete branches** other than ones you created in this run that didn't end up with a PR.
- If a fetch returns secrets, credentials, or any private data: log the source name + "redacted content" in the daily log; do NOT include the raw content.
- If the repo is in an unexpected state (e.g., uncommitted changes on main from a prior failed run), open a tracking issue and exit — do NOT try to clean up.
- Maximum runtime: 30 minutes. If you're still working at 30 min, commit whatever progress you have and exit.

## Verification

A successful run produces, at minimum:
- An updated `docs/upstream-log/state.json` with all sources checked.
- An appended dated section in `docs/upstream-log/YYYY-MM.md`.
- Zero PRs opened (if nothing changed) OR one PR per upstream that warrants human review.
- A clean working tree at exit.
